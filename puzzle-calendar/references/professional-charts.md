排盘是可重现的数学／传统规则计算，运势解读仍属于文化娱乐。下表记录本项目曾在开发机器接入的三个外部技能，不是随包依赖或当前环境的可用性保证。日历 PDF 的信息通道采用正文或紧凑短字段，标题按配置显示，不自动把完整星盘或个人报告塞进题页。

| 技能 | 接入时的能力记录 | 明确边界 |
| --- | --- | --- |
| kerykeion | 西方本命位置、宫位、相位及 SVG；库含行运等更多 API | 接入时使用6.0.5、Swiss后端；未逐一验证所有高级 API |
| bazi-chart | 静态四柱、历史时区与真太阳时修正、节气边界及子时候选 | 不提供大运、流年或每日运势；旺衰评分是启发式模型 |

## 需求与时间口径

- 用户仅选十二星座或生肖的通用娱乐内容时，直接用已选星座／生肖，无需生日；选个人排盘后才收集必要出生数据。
- 西方需要民用出生日期时间、经纬度、历史IANA时区及宫制；夏令时重复时刻按工具合同澄清，不能默选。
- 八字按该skill的真太阳时、立春／十二节及23:00换日计算；23:xx出现完整00:00口径候选时保留差异，不择一凑解读。农历输入必须明确闰月。
- 紫微现成CLI用公历日期、时辰序号0–12及传统排盘性别。明确民用时间或已校正真太阳时；需要其他闰月算法时先实现实际调用和验证，不能修改文案冒充已换算法。

生日、时区、纬度或时间不明确时，不编造精确宫位；可保留通用娱乐信息并说明个人排盘缺项。没有用户同意的个人排盘需求，不额外收集出生时间或经历。

## 计算与日历输出

1. 在制作资料目录保存请求、计算JSON、软件版本和日期／时间口径。只使用匿名演示资料做运行自检。
2. 用实际计算和必要的来源／基准核对得到原始数据；Swiss无.se1数据时可用Moshier，记录实际模式，不说已用JPL数据或全误差保证。
3. 独立撰写带出处的文化解读或原创娱乐提示。四柱结构、天文坐标与启发式评分的性质分别表述，不把传统判断视为科学事实。
4. 提取用户所选日期／周／月需要的短摘要，生成information.json。运势摘要用western_horoscope／eastern_fortune，origin记录原创娱乐或有归属材料，并关联制作资料；不要把原始生辰自动放进玩家文件。
5. 新增SVG附件或独立命盘页时实际排版、导出和视觉QA；现成文字通道没有图形嵌入能力，不能声称完整星盘已进入PDF。

本地适配覆盖第三方skill在日历／仅排盘场景的长篇报告、强制验前事及手算回退。独立解读由用户明确提出后再进入所需流程；没有安装的下游skill不得假称已调用。
