# 日历种类与可选信息

## 真实日历形式与日期

| 形式 | 正式页面的基础信息 | 当前运行能力 |
| --- | --- | --- |
| 月历 monthly | 年月标题、该月全部日号、星期列，真实4/5/6行布局 | 每月一页；每页一题的模板已接通 |
| 周历 weekly | 完整起止日期、每一天月日与星期；跨月跨年按真实日期 | 每周一页；每页一题的模板已接通 |
| 每日历 daily | 明显的月份和日号、完整年月日、星期；成组显示无需再重复ISO行 | 每天一页；每页一题的classic／editorial骨架已接通，内部题号默认不印 |

日期范围、阅读制式与出题频率分别决定。全年可以是每日／周／月内容页，也可以另行设计年总览；当前一页一题链路不包含单页年总览。桌历、挂历、撕页是使用或成品形式，现成工具提供内容页，实体工艺另验。日历索引＋题册、同页多题等组合仍需另行排版与验证。

使用datetime/calendar计算公历，确认有效日期、闰年、月长、星期、跨年周、邻月显示与题位归属；导出前重新派生全计划。基础日期不可由用户信息表或语言模型文案覆写。日期计划测试覆盖上述主要边界；测试通过不表示任意新模板都免于日期／视觉核对。

## 用户可选信息

| 类别 | 选项与最少必要细节 | 内容规则 |
| --- | --- | --- |
| 传统历法 | 农历、干支、生肖、二十四节气；需要地区／时区及必要的历法口径 | 使用实际历法库或可靠日期表，记录版本与来源；春节换年与立春口径不能混用 |
| 节庆事件 | 法定节假日、调休、文化节日、纪念日、生日 | 法定安排核对地区与目标年份；文化节日与放假分开；个人事件标为用户提供 |
| 西方星座 | 星座知识、选定星座的日／周／月运势，或十二星座摘要 | 星座知识核对来源；运势可用原创娱乐内容、用户材料或获准来源，归属与性质写入metadata并在回复／交付说明披露 |
| 东方运势 | 生肖运势、黄历宜忌，或明确指定的八字／紫微等个性体系 | 不把不同体系混成一套准确预测；先明确想选哪种。没有实际排盘能力时说明缺口，不假称算过 |
| 阅读与趣味 | 每日格言、诗句、历史小知识、冷知识、正向提示 | 原创句不挂名真人；引述与知识核对来源，保留署名和合理引用范围 |
| 普通随手记 | 备忘、日程或任意短记，空白／横线／点阵均可 | 随版式需求安排有效可写区，不要求先启用记录功能；不把视觉间隔或装订空白当作可写区 |
| 专用记录与跟踪 | 解题用时、卡点、解题完成勾选、心情、习惯、目标等 | 明确用途后按需加入；标题与字段写清主题，不把普通备注混入该选择条件 |
| 天气等时效信息 | 有地点与日期的有效预报 | 保存获取时间与有效期；未知未来天气不编造，制作全年纸历不承诺全年真实预报 |
| 自定义 | 用户提供的其他信息 | 先识别是事实、创作还是个人事件，再采用相应核对与版面处理 |

随手记与专用记录的定义见 [需求收集](intake.md#书写空间与专用记录)。信息通道的text／fields是预先印刷内容，不会自动生成供手写的空白或划线表单；书写区仍需实际排版。

按日期或月／周阅读节奏放信息，不默认每天塞入全部十二星座或所有生肖。用户已选星座／生肖时直接使用，不另索生日。仅在用户选择需要个人出生信息的体系、且实际工具支持时，才说明所需字段；不默认收集身份证等无关信息。

信息块标题默认隐藏；玩家页面不印“娱乐”等性质标签，也不印来源状态、内部编号或生成说明。来源可以是原创娱乐文案、用户提供或有归属的来源内容；不能把原创说成某位大师／平台的结果，也不能把娱乐文案记成已验证的事实。模块kind、classification和provenance继续保存在制作资料，在回复或交付说明中说明其创作／文化性质及来源。用户开启标题时只显示有用的内容标题，不自动拼接性质标签。

## 黄历式信息块

参考[马上默黄历](https://www.masmo.cn/tool/chinese-almanac)与[RECATOOLS黄历](https://recatools.com/daily-chinese-almanac/)的日期头、宜／忌并列和其他明细分区。这里采用的是字段组织，不能照搬页面对历法正确性的宣传作为本工具验收。图像检索定位了纸质样张，但浏览器截图未成功，未声称逐字统计或量测该实物；以下字数与mm均为本产品设计目标。

默认一块含2–6个用户选定字段，值以2–4字短词为主；宜／忌每栏2–3项，当页运势总正文合计约20–50字作为初始目标。兼开多个体系时合并规划短字段和空间，不对每个体系重复分配长段。公历日期为第一视觉层级，月份与日号组成明显的日期组，星期／农历为次级；宜忌或运势为一个紧凑块，采用横排两栏，标签12pt加粗、值11pt。标题默认隐藏且不加性质标签；用户开启标题时用9.5pt。当前helper栏间8mm，并在各栏内对齐值。editorial将信息块放在题板和板下题名之后，下方范围按所有模块实际高度测量；放不下明确失败。A5信息块约20–30mm高可作多字段起测值，少字段不用凑足高度；不把这些数值当成任何纸质黄历的实测值。

现成helper新增可选fields格式：每块1–6项，每项只有label与value，label最多4字符、value最多16字符。输入上限不是推荐文案长度；字段的实际字体宽度也必须放得下。text和fields二选一，避免同一模块隐藏或重复印刷一段长文。字段不适配明确失败，不自动换行、截短或降字号。

```json
{
  "module_id": "compact-demo",
  "kind": "almanac",
  "title": "运势排版示意",
  "fields": [
    {"label": "宜", "value": "沟通 整理"},
    {"label": "忌", "value": "争执 熬夜"},
    {"label": "节奏", "value": "从容"},
    {"label": "心态", "value": "平和"}
  ],
  "provenance": {"origin": "original_entertainment"}
}
```

这些词条是单块合同示例，不是某日通书或个人排盘结果。多日示意样页分别准备相应日期的文案，并在交付说明标明其示意／原创娱乐性质；不能将同一组占位宜忌复制到不同日期后冒称实际每日运势。真实内容依用户选择、来源及计算数据填写；不凭空加吉时、方位、幸运色、分数或未经选择的健康／财富结论。不同类别的事实与娱乐来源规则保持原合同。

检查相邻日期的信息内容，发现整块重复时核对成因。相同节假日、事实、周期内容或来源本来给出相同建议可以保留，并在制作记录中保存依据；用户问及重复时说明原因。原创日运势样文不应因复制占位而连续相同；若创作意图就是多日同一主题，要明确说明。不要将“不重复谜题”的验收泛化成“所有日历信息每天必须不同”，也不要为制造差异改写真实事实。

寄语或诗句可继续用text短句，约15–25字、最多两行作为起点。所有类型最终按实际纸幅、栏宽、字号和PDF测量，多模块合计高度也要检查。不为长文挤占谜题作答空间；详细依据另附，用户明确要求长文直接印在题页时重新设计并展示样页。

## 运行信息合同

`page_information.py`负责结构与显示合同，不执行天文／农历计算、取天气、验证来源真伪或预测运势。主控先取得并核对事实内容，或按用户选择创作娱乐内容，再生成 `information.json`。新任务把信息文件注册为job的information角色，由prepare导出可再生输入；不在任务记录外另维护一份需求，见 [workflow.md](workflow.md)。

```json
{
  "schema_version": "1.0",
  "entries": [
    {
      "page_id": "page-daily-2027-01-01",
      "date": "2027-01-01",
      "modules": [
        {
          "module_id": "horoscope-aries",
          "kind": "western_horoscope",
          "title": "白羊座今日提示",
          "text": "把一件想做的事拆成容易开始的小步骤。",
          "provenance": {"origin": "original_entertainment"}
        },
        {
          "module_id": "personal-event",
          "kind": "anniversary",
          "title": "我的纪念日",
          "text": "留一点时间记录今天的心情。",
          "provenance": {"origin": "user_input"}
        }
      ]
    }
  ]
}
```

以上日期、星座和文案是合同例子，不默认加入实际日历。page_id必须来自完整计划；可选date必须属于该页实际覆盖的日期。其他显示日期需在相应事件文本中明确，不拿相邻月弱提示日期重复派题。风格样页选页时仍用完整计划验证信息映射。

事实模块（lunar、solar_term、holiday、observance、western_sign、chinese_zodiac、ganzhi、weather）需要 `provenance.status=verified`、非空source和method；这是对来源核对记录的结构要求，不能仅手填verified就声称事实正确。未核对／过期数据不进入最终页。

western_horoscope、eastern_fortune、almanac在metadata中自动归类entertainment，该分类不转为印刷标签；quote和custom记录原创／用户提供／归属来源；anniversary与habit记录用户事件／跟踪用途。模块类型、重复ID、缺来源、非法日期、页外事件或过长文字均明确拒绝，不悄悄截短。

## 排版与交付

原生renderer、扩展renderer和extended_job通过 `--information PATH` 读取，并通过 `--appearance PATH` 控制layout、强调色和标题等显示。信息按选定页面绘制，并计入可用题区；cyber-noir 1.2将节日／节气归日期区，其余editorial预设尚未统一这一信息路由，新增使用需实际核对；相同日期／信息与题面保留在对应答案页中，内容不改变题目或唯一性证明。模块title仍是内容字段，默认不打印；`show_information_titles=true`才显示标题，不自动加“娱乐”。来源分类留在metadata，性质与来源在回复／交付说明披露。editorial仅支持竖版每日页、reference／none且show_rule_hint=false；不支持的组合拒绝，不静默改变规则或版面。

```text
PYTHON SKILL_DIR/scripts/render_calendar.py --plan FULL_PLAN.json --records RECORDS.json --information INFORMATION.json --output-dir NEW_DIRECTORY
PYTHON SKILL_DIR/scripts/extended_job.py --plan FULL_PLAN.json --types futoshiki,lightup,hitori --source-project SOURCE_PROJECT --information INFORMATION.json --output-dir NEW_JOB
```

现成信息通道渲染正文或紧凑两栏字段，标题按appearance配置显示；天文星盘图、专业个性排盘、复杂黄历表格、交互打卡或信息块图片不是这个通道的已实现能力。页脚logo属于独立页面显示配置，不等于已支持任意图片信息模块。需要这些形式时另行实现并验证。

新增信息时重新测量字级、线索、规则、格距与装订区。空间不足先减少装饰和在既定要求内重排，再筛选适合的题型规格；锁定题型／信息无法同时放下时集中说明选项。不能为了展示运势而缩小基础日期、删线索或降低作答空间。


## 真实女性寄语与署名

用户选择真实人物寄语时，逐条核对原话、原作或可靠机构保存的原始记录。短译保留原句、原语言／中介译本、中文短句、作者及身份年代、原始URL与定位；作品人物台词署名带作品名，不写成作者的个人演讲。不得原创励志句后挂名真人。正文用quote.text，署名用quote.attribution（最长50字符，9.5pt右对齐），只支持text，不与fields混用。来源和核查说明另附，不挤进日页。

法定节日名称与年度调休分别取得。年度通知尚未取得时，只标有依据的固定节日，周末不冒称确定放假或补班；在回复／打印说明披露范围，通知取得后更新信息即可，原题与日期不变。
