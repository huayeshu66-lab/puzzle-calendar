# 设计评审：美感、阅读、书写与整本节奏

设计是否成立取决于brief里的用途与优先级。排版边界检查、字体嵌入和单元测试是必要的技术证据，不能替代实际看页面；“由模型做设计”本身也不是问题，关键是判断是否有依据、经过画面检验且可以续做。

## 先辨输出类别，再看真实成品

交付说明明确区分“概念预览”和“可打印样页／正式PDF”。`image_gen`可制作原创装饰或配色、构图概念图；生成图中的日期、汉字、格盘和线索不能作为正式内容依据。可打印输出须从日期计划与已验解结构数据排版，将合格装饰作为独立资产放入真实PDF。两类都可以交付；概念PNG不能自动通过尺寸、题目正确性或打印检查。

用最终PDF渲染当前版本预览，先看整页，再按成品尺寸放大文字与题面。预览记录绑定其来源PDF的当前哈希，渲染图另存自身哈希；参考图、旧PNG或只看代码都不能当作新版已经过视觉检查。
标作“局部放大”的图必须来自同版整页或准确题盘的实际裁切／渲染；另行生成、添加细节或与整页不一致的近景只能称“细节设计示意”，不能据此声称整页已经采用该处理。

代表页选实际风险：日期信息最长、题外线索最多、长题型名／署名、首次完整规则、跨月、最拥挤模板、大字或装订约束。数量由风险决定，不机械把每个题型都乘所有样式。已有内容换样式时锁住同题同日，便于判断真正的设计变化。

## 同题比较看整页，也看题面

不同方向应在整体主视觉、构图、字体角色和纹样节奏上形成可辨区别，并说明这些选择如何服务用途。仅替换字体或颜色，或在相同布局上随手贴叶片、圆圈，不足以成立为不同风格。页面与题面可以共享母题：例如植物刻线呼应黑格肌理、页边波纹延续到填纹、排线呼应书页边框，或圆角贯穿日期块与格盘。这些是可选方法，不是每次必加的装饰清单。

## 繁简与主题共同设计

分别判断主题／气质、构图、装饰密度、配色和题盘参与程度，不把它们捆成固定套餐。适中、丰富或极简都可服务不同主题；当前项目的“适中但有特色”不应变成全体用户的默认审美。按照 [风格访谈与确认](intake.md#不知道风格时) 获取有意义的偏好，已明确或已委托时直接执行。

先用主视觉组织日期、插画／纹样与题盘的位置，再确定信息层级、线重、黑白／色块面积和连续留白。修改繁简程度时重新审视这些关系：适中稿应有完整的主题表达，不能只是极繁稿删掉部分花边；丰富稿要有阅读重点，不能靠覆盖所有空白显得完整。用户否定既有主题时允许重选题材与表现形式，不把旧四款或任何固定库当作穷尽选择。

用户选择题盘一起设计时，同时落实格线、浅底色／分区填充、数字字面、节点／圆圈、外框与规则允许的轮廓；比较完整页和题面近景，检查题盘是否延续主题、有效作答面积是否仍足够。只给标准题盘换外框不能冒充全面协调。用户选择保留标准题盘时尊重该选择，不强制增加纹样。

黑白稿用可印的线重、排线疏密、浅灰与正负形建立层次，不直接把彩色转灰当作设计完成。数字、线索与作答区保持足够对比，底纹不盖住铅笔痕迹；装饰不暗示答案、不冒充新增线索或区域规则。评判繁简不机械依赖一个装饰面积百分比，要看目标尺寸下的实际阅读与书写。

## 题面重绘与规则边界

题面可按整体风格重绘字体、线条、填纹和外轮廓。原始结构坐标留存作为核对依据，派生稿允许经过检查的位置和曲线映射；保留线索、面归属、邻接／连通关系及答案语义，不把源坐标当作所有风格的固定外观。线索数字周围留净空，装饰不能像新增线索、答案标记或可通行边界。圆角、间隙和描边会占用格内空间，应按实际成品尺寸测量有效作答面积，不能只报中心格距。

用户要求真实六角、三角、圆形或异形结构时，先按 [题盘形态](puzzle-forms.md) 选择相容玩法；这是可能需要重新出题的结构选择。只省略装饰框可沿用原题，改邻接关系／裁剪有效单元则必须重新生成和验解。自由轮廓不额外套方框；保留参与规则的边、墙、区域和入口。

蜂巢数回未指定整体形状时，审看默认类六边形簇的六向均衡、紧凑比例与自然收边；不能仅因每个格子是六边形就接受长方形阵列作为默认。用户明确指定的其他轮廓不受此默认限制。

原始题板、源哈希、`puzzle_id`、结构数据及答案保留；派生矢量单独保存并有独立哈希。重绘后从实际PDF核对线索位置、格盘和答案对应，再看清晰度与落笔空间；原源板通过的证据不能自动证明派生稿通过。若尚无可靠的结构核对与重绘能力，保留原题板，只调整其外部设计。

## 让题盘本身表达风格

从用户已选风格和题盘结构寻找相容意象，再具体决定线条、填充、节点／圆圈和轮廓怎样共同表达它。东方古典可以探索莲蓬、石子、团扇；赛博风可以探索电路节点、机械环；这些是候选意象，不是风格与图案的固定配对。用户举例允许的是设计方法，不能据此替所有项目选择东方风或莲蓬。

把改动分清：

- **外观处理**：线宽、连续笔触、浅填充、岛屿圆圈／符号、规则外的轮廓可协调变化；题目中的黑格、墙、预填边等语义标记仍须一眼可辨。
- **保留结构的重绘**：数回的边可适度弯曲、节点可作连续位置变换，只要每个节点、边、面一一对应，连接次序和线索归属不变，没有新交叉、断口、合并或遮挡。答案使用同一位置与曲线路径映射。桥梁的横竖对齐、相邻关系和不可交叉条件属于规则，不能为图案随意弯桥或挪岛；整行整列保持顺序的间距调整可以另行验证。
- **改变题目结构**：增删单元、改变邻接或连通关系时先确定新图，再重新出题、验解与去重，不能沿用旧答案。

**蜂巢数回 → 莲蓬示例。** 用紧凑蜂巢簇作为骨架，整体形成自然、略起伏的莲蓬盘面；可将边适度柔化，浅墨填充形成表面，莲子般的浅色区域承托清晰数字。每个单元仍保有可数清的六条边及共享节点，不能把六角格替换成互不连接的独立圆圈。莲子意象可用于每格一致的浅色底形，不用粗黑封闭描边制造额外“回路”，也不以装饰的个数、深浅或有无暗示答案；基于已公开线索区分样式时仍须避免看成新规则。保留明确白色落笔区域，数字不使用难辨的书法字。

先以实际题目做题盘近景和整页样例，检查风格是否来自题盘自身，以及读者能否无需额外解释分清哪些线能画、哪些标记是线索。同步检查线索与源数据的一一对应、共享边没有错位、答案沿相同的派生边绘制、细笔触无假断口、浅填充在目标打印条件下不妨碍落笔。设计变换记录在当前 brief／制作资料，沿用已选方向，新增未确定方向先供比较。

上述是设计与核对方法，不代表现有绘图器已内置莲蓬或任意曲线变形。需要时实现相应矢量路径及题面／答案映射，验过真实PDF再交付；生成插画可提供纹理或概念，不能代替准确谜题层。

### 题盘与主题造型融合：主体细密，书写区留白

这是一种可选的构图思路，不是“极繁”的替代名称。适合用户希望题盘本身参与主题表达、又需要清楚落笔和随手记的情况；也可按其他主题、纸幅与繁简偏好重新设计。

- **先让结构成为主体。** 从题盘的整体轮廓、单元和空区寻找相容意象，让它们共同构成一个物象。蜂巢格可以对应莲蓬种孔；仅在标准格盘旁贴一片叶子、套一圈花框，不等于完成融合。具体意象要顺应本题规则与用户偏好，不把莲蓬固定为东方风的默认图案。
- **细节从主体结构生长。** 刻纹、凹凸、线重和疏密分别服务于种孔、表皮、外缘等部位；用连续的层次组织丰富感。辅助叶片或柄有承托关系，并核对其形态特征。在莲蓬意象中，避免把每格都装成一朵小花；不靠无关花边填满所有空白。只有纹理数量增加，不能证明构图更丰富或已达到极繁。
- **先分配真实使用空间。** 把日期阅读、题面落笔、普通随手记与专用记录分别安排，再确定装饰范围。随手记应有连续可写的空白，不能只剩标题后的一条短线；统计净宽、净高与行距，不把装订区、视觉间隔或图案间碎空算进去。空间不足时重排主体与模块，不能靠难以辨认的小字或名存实亡的记事区腾出装饰面积。
- **画稿与准确内容分开。** 可先按已验解题盘做准确构图参考，再细化主体画稿；数字、共享边、节点和答案由原始结构另行排入。必要时沿作答路径留出清楚通道。逐格核对种孔与线索的对应，并检查真实PDF整页与局部；画稿看起来对齐不代表题意已经正确。

**已获美感认可的案例：细密刻纹莲蓬样页。** 37个蜂巢单元对应同一只莲蓬的37个种孔，细节集中于孔缘、表皮和外沿，一片局部荷叶与短柄承托主体；页底另留完整记事区。A5黑白样页采用124 × 27 mm记事净区、约1.34 mm题线通道及独立玩法／答案页。这些是该样页的实测选择，不是所有日历的通用下限，也不代表已有一个可直接传入的莲蓬 `style_id`。

**认可范围要逐项记录。** 用户反馈“这个很好，是好看的。虽然不是我要的极繁，但也是一种思路”，支持保存这一设计方法和本样页的美感认可；同时必须保留“未达到该用户的极繁要求”。这不等于已选择整月／全年风格、授权批量制作或完成实物试印。后续探索极繁时仍依据用户目标另行设计，不能把这个案例作为极繁达标证明。

### 主题物与日期对应

主题物不仅要与题盘形态相容，也要与页面日期相符。这项检查覆盖题盘造型、插画、背景纹样及辅助物件。先沿用已知的目标年份、使用地区和日期范围，再安排主题；不能只因某个造型好看，就把它放到任意月份。

制作记录写清“主题物 → 呈现状态 → 适用地区与时段 → 实际选用日期 → 依据与匹配结果”。整月／全年先安排主题时间表，再展开页面；这是制作工作，不要求用户填写技术字段。地区不明且会影响选用时，补问必要信息；尚未核实时保留为季节意象或待定，不声称当地此时正在盛放／成熟。

- **自然物按实际生长阶段安排。** 植物分别考虑花、果实／种荚、叶色和干枯状态，结合地区、半球、气候及品种核对时段，不把花期直接当成果实成熟期。此项目的莲蓬优先安排夏季日期；鲜莲蓬与舒展荷叶形成夏季意象，具体窗口按使用地区核实。干莲蓬／残荷可另作秋冬主题，但画面必须确实表现该状态。黑白、刻纹、低饱和不自动等于干枯，不能事后改称“干莲蓬”来掩盖日期不合。
- **节庆物对应具体年份和文化语境。** 节庆、纪念活动、生日等依当地历法或用户提供的日期安排；适用时段可包括合理的节前／节后窗口，不必只在节日当天出现。节日日期、法定放假与文化意象仍分开核对。
- **季节关系不用机械切日。** 自然物的适用窗口不必在某个节气当天开始或结束，也不强制全国共用月份表。常年可见物、抽象几何或明确不受季节限制的主题，可记录“无特定季节”，不强行配季。用户明确指定的反季节、幻想或个人纪念主题可以保留，在制作记录中说明理由，不冒充自然物候。

导出前按真实日期复查各主题及其状态。窗口未知或日期不合时，按已有授权核实、换相容主题或调整选用日期；改日期须重新计算年月日、星期、农历、节气和节假日等已选信息，并更新题目与答案的位置映射，不能只替换大日号。范围或已确认安排受影响时再补问必要取舍。

**现有莲蓬案例的时间边界：** 2027年1月1日样页沿用了同日同题的造型比较底稿，用户认可的是美感思路；它没有通过此项目的夏季主题匹配。保留为造型研究，不直接作为元旦正式用页，也不悄悄修改已冻结的比较稿。后续采用时优先放入夏季计划，再核对所选地区、日期和整页信息。

物候核查示例：[美国国家公园管理局的莲生命周期](https://www.nps.gov/places/information-panel-life-cycle-of-a-lotus.htm)描述夏季开花及种荚随后成熟、干燥的过程；[邱园的莲介绍](https://www.kew.org/plants/sacred-lotus)说明干莲蓬可用于插花。这些支持区分植物状态，不提供中国各地统一月份表；夏季、秋冬等页面安排仍须结合目标地区与用户意图判断。依据记录在制作资料，页面不增加无用说明。

## 认可与达标分开记录

把用户反馈落实到所指版本和具体目标，沿用 [任务合同](workflow.md) 的design资料及既有审阅字段，不发明新的CLI开关。

| 判断 | 依据与记录位置 |
| --- | --- |
| 喜欢某个构图或细节 | 保存真实原话、版本与认可部分；不覆盖尚未满足的要求 |
| 达到要求的风格 | `visual.criteria.style` 对照当前brief的主题、繁简、配色与题盘处理；好看但不符合指定极繁时记failed，尚未判断记pending |
| 主题与日期匹配 | 在design资料保存地区、物候／节庆依据与匹配结果；未知时待核，不因视觉认可升级 |
| 允许批量采用 | requirements／decisions记录用户选定或明确委托及范围；仅“好看”“作为思路保存”不构成批量选定 |
| 实物可用与难度合适 | physical_print／human_difficulty各用实际试印或试玩证据，不由屏幕预览推导 |

某项未达标不抹去已获认可的部分，也不阻止交付标明缺口的比较样稿。若用户明确改选替代风格，更新brief并复核当前输出；不能为了把审阅填成passed而擅自改掉原目标。当前helper只核记录与文件一致性，不会自动判断风格、物候、引语真实性或用户授权。

## 主题的呈现阶段

主题可以在题面中成立，也可以在解答完成后显现，或分两阶段展开。它影响玩家看到什么，不只是换色选项；题型与物象配对集中见 [题型与主题造型储备](puzzle-forms.md#题型与主题造型储备)。

- **题面即显。** 只依靠公开题盘、线索与不依赖答案的装饰表达主题，例如桥梁的荷叶岛屿、数和的镂空骨架。若主题外轮廓本身就是题意（如拼块填形的目标轮廓），可正常显示。
- **解答后显现。** 玩家作答形成图案，或在完整解答上强化物象，例如银河的对称花簇、矩形分区的博古架、地图着色的完整彩窗。依赖答案的分区边界、桥线、灯位、填色和纹理只在所选答案载体中出现。指定主题要求制约解答结构时，要据此生成并重新证明，不能把任意解答贴上名称就算主题成立。
- **双阶段呈现。** 题面提供不泄题的主体和气氛，答案补全结构或图案。准确答案层仍须能单独辨认；艺术化展示不能遮盖判断正误所需的线、格或数字。若完整艺术图需要改变比例或重排结构，另附展示图，不用它替换与题面一一对应的准确解答。

制作资料记录呈现阶段、题页可见元素、答案专属元素、题目／答案对应关系与实际检查结果；用现有design资料和brief表达，不新增未经实现的CLI参数。题盘几何与线索保留同一映射，准确答案板遵循既有位置／比例要求。独立册、随机背面、二维码等交付方式均采用同样的区分。

先单独看题页，再与答案比对：装饰、留白、深浅、图案方向和题名是否额外指示正确分区、连接或填涂？除了已声明的公开线索，不能借装饰编码答案。展示样页时分开题面预览与答案预览；玩家版封面、缩略图及二维码旁的示意图也不提前展示该题完整答案。需要玩法例子时使用独立例题。

主题成像质量与谜题正确性分别验收：图案好看但答案错误不通过，唯一解正确但看不出所选主题也不能声称主题已经实现。没有开发相应题型或绘图器时，保留为设计储备；用户同意收录该方法不等于所有主题已完成制作或整年样式已选定。

## 五个独立标准

| criteria字段 | 看什么 | 常见失败信号 |
| --- | --- | --- |
| hierarchy | 一眼能辨日期、任务主体与次要内容；日期字段彼此成组，内容顺序符合使用方式 | 所有字一样大；月份藏在远处；寄语／标签抢过题面；重复总标题占位置 |
| readability | 字形、中文标点、题面符号、线索、行长与断行清楚；短规则能直接理解 | 仅缩字使之放下；难懂的术语串；孤字尾行；竖排标点误转；细线看不清 |
| style | 整体主视觉、构图、字体角色、配色和纹样节奏表达适合用途的设计判断，题面与页面关系成立 | 仅换字体或颜色；随手贴图形；题面像孤立贴图；为了显风格加无意义英文／条码 |
| spacing | 区域间净空、基线、边距、装订区和文字内间距有节奏，空白有作用 | 字挤成团；线框擦过线索；版面散成多个孤岛；满版装饰侵入题区 |
| writing_space | 格盘、候选数字、画线、涂黑和手部活动有足够区域；圆角／间隙后的有效作答面积足够 | 只量格距；外部线索未计入；题板能看却无法写；临近装订边难下笔 |

五项分别下判断，不用“边界未越界”同时代替美感与书写。允许多种审美：满版彩色、克制黑白、古典书页、可爱几何都可成立，前提是符合该项目brief和真实打印条件。字数、字体家数、竖排和规则频率是具体方案的选择，不是所有日历的统一标准。

对于读者无用的制作状态、内部ID、性质标签、假功能装饰等保留在制作资料或交付说明。若用户实际需要导航、页码、品牌或教学标签，则按用途设计，不能因为某次样页删除过就永久禁用。

## 阅读次序和区域关系

检验用户第一眼看到什么、第二眼去哪里、做题时是否受打扰。节日／节气通常应随日期阅读，寄语是另一阅读区；实际选择可因日历用途调整，不能把一个特定预设的路由当作所有模板已支持。

检查书写用途是否清楚：视觉留白不等于随手记，普通备忘不等于解题跟踪。用途与空白／横线／点阵的外观分别记录；专用区用“解题草稿／解题用时／解题完成”等明确主题，普通书写不强加这些字段。实际有效面积不包括装订禁区、视觉间隔或格内描边。

规则按使用方式提供：连续整本可以集中，独立分发需要足够条件。提示必须能被读懂，不能把短术语当完整规则；陌生玩法短句放不下时，重排或另附，不删条件。

竖排适合少量短汉字标签，逐字正向排；标点、拉丁文字、时间与长段落需相应排版能力。没有完整竖排字体／标点处理时使用横排或明确限制，不能将整行旋转90度后声称支持中文竖排。

## 整本节奏单独检查

先扫查当前scope全部题页与答案的缩略图，再放大风险页；记录扫查和细查各自范围。检查日期位置、类型切换、题面大小变化、信息有无、疏密交替、月份过渡和答案对应是否有稳定逻辑。

稳定不等于每天完全一样。变化应来自真实题目、必要内容和有计划的主题，不靠每天随机换字体或装饰色。用户明确要求按月换字面时，可维持同月角色与尺度，分别验证各月的实际实现。

同一日期的题页和答案仍需同范围题板，不能为答案省略规则后突然扩大棋盘。不同规则、网格和外部线索的自然大小差异应合理，不用强行把所有题面缩成一种面积。

当前只做一月就只评价该月节奏；未生成月份的计划可以审，但不能写成已目视看过全年。

## 记录真实观察

将visual review注册到job，并包含当前calendar及answers的artifact_id／hash、reviewer、五项criteria的status与notes、总体发现和coverage。coverage为每个PDF列page_count、reviewed_pages、method、enlarged_pages。至少一个preview绑定这些当前PDF；多图时记录各自覆盖。

题面重绘另记原源板与派生稿的哈希对应、语义核对方法和结果。概念预览记录用途与未验证项目，不登记为可打印PDF检查通过。

有效说明应能复核，例如：“31页题页／答案缩略图扫查，放大1、5、14、20、31日；五字题名完整，20日外部线索与日期线分离；未见截字；实物落笔未试。”不要只写“高端／审美在线／测试通过”。

发现问题后按影响改动：字体或分隔线问题追查同模板；一条长署名只重排该页；换题仍要内容与全局去重。改后生成当前预览，旧PDF／旧截图证据不能冒充新版本；未影响且hash不变的源证明可保留供复核；最终审阅仍需匹配当前需求／brief与输出，具体绑定合同见 [workflow.md](workflow.md)。

## 三个不能互相代替的结果

| 结果 | 证据与边界 |
| --- | --- |
| 数字版设计检查通过 | 已看当前实际PDF，五项与整本节奏符合brief；记录内部检查范围 |
| 用户认可 | 真实样页反馈或明确验收；未知风格先供用户确认，明确委托自主定稿才可跳过；委托不记为本人目视认可 |
| 实物／真人体验 | 打印尺、纸张、设备、落笔或试玩的实际记录；屏幕预览不能证明 |

没有实物证据保留physical_print=pending，可以交付说明准确的数字版；没有用户审阅不假称认可。合法未完检查可以作为trial交付，不能把待阅样稿写成最终已验收生产件。
