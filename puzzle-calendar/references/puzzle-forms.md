# 题盘形态：网格、轮廓与边框分别选择

用户要六边形、圆形或不规整题面时，先看玩法能否原生支持，而不是把正方形题裁成相应外形。需要区分四项：

- **规则家族**：数回、迷宫、桥梁等；同族换网格不虚增题型数。
- **网格结构**：方格、蜂窝六角、三角、极坐标环带、离散节点。结构改变后，邻接与计数规则也要相应重建。
- **整体轮廓**：矩形、圆形、自然锯齿、遮罩异形。蜂巢数回在用户未指定时默认选择紧凑、均衡的类六边形整体轮廓，优先近六向对称的完整蜂巢簇；六角单元本身不构成整体美观的保证。
- **边框处理**：保留规则所需的边界，只省略装饰性外框。迷宫墙、数回候选边和分区边界都不是可随意删掉的装饰。

把选择写入当前任务的制作简报或已支持的自定义记录，不向现有 CLI 传它不识别的 appearance 字段。

蜂巢默认轮廓的判断看整体而不只看单格：各方向延展均衡、边缘自然收束、无突兀长条和孤立凸出单元，等比缩放后与页面留白协调。由完整六角单元形成的微锯齿边缘可以保留，不额外套一个正六边形装饰框。用户明确要长方形、带状或其他轮廓时，按指定轮廓另行生成；不能以审美默认覆盖用户选择。

基础形态也可以按风格表达为具体意象，例如东方古典风的蜂巢数回探索莲蓬。线条、浅填充和圆圈／节点可一起设计；数回共享边与面、桥梁横竖连接、迷宫墙和入口分别保留其规则意义。保持结构的一一对应重绘可沿用原题；改结构则重新生成。具体方法见 [让题盘本身表达风格](design-review.md#让题盘本身表达风格)，不把当前绘图器的直线外观当成审美上限。

## 题型与主题造型储备

先匹配再选形：主题已定而题型未定时，比较主题物与玩法中节点、通路、区域、数量或对称关系的契合度，再核实生成与验解能力。比如海岛可对应桥梁的节点，海面留下横竖作答通道，太阳承担日期区的视觉平衡；不只因太阳是圆的就套圆形迷宫。题型或样题已冻结则保留它，另找兼容表达，不擅自换题。下表为启发示例而非题材白名单，完整方法见 [极繁设计方法](maximal-design.md)。

以下方向已获用户同意收录为可选设计方法，不代表已选定某本日历的全部主题，也不限定未来用户的审美。根据纸幅、风格、繁简、季节、实际玩法和依赖能力选用；区分改变外观、改变真实结构与答案完成后形成图案。呈现阶段及防泄题要求见 [设计评审](design-review.md#主题的呈现阶段)。

| 题型 | 对应主题造型 | 结构与规则边界 | 当前能力 |
| --- | --- | --- | --- |
| 桥梁 Hashi | 群岛、池塘荷叶、庭院卵石、机械节点 | 岛屿承载数字，不强加整体外框；保留横竖对齐、可连相邻岛、单／双桥与不交叉关系。改变间距须验证规则关系及落笔净空，不随意挪岛、弯桥 | 已有无框与黑色岛屿绘制；具象荷叶／石子／机械节点外观仍需绘制、检查 |
| 地图着色 Map | 冰裂瓷纹、彩色玻璃、拼布、叶片分区 | 不规则分区参与构图；保持区域邻接与预填线索。黑白可用四种明确符号／纹样表达类别，并提供图例；题页只标已知类别，不能提前填完整配色 | 已有矩形外轮廓与不规则内部分区后端；上述主题处理及圆形／叶形外轮廓未内置，后者需另行构造或验证映射 |
| 数和 Kakuro | 十字窗花、阶梯轮廓、镂空窗棂 | 利用白格串、黑格和空洞设计骨架，再生成和数；保留横竖格串、线索归属及串内不重复规则，不能裁掉已出题格子 | 有受限小规格实验后端；足以表现窗花的规格、异形结构及主题样页均需新增实现与验解 |
| 点灯 Akari | 宫殿平面、庭院、阶梯灯笼、城市街区 | 黑格表现墙体，白格表现照明空间；墙、边界和横竖光路须清楚。未求解题页不预画灯位、正确光路或答案光晕；不规则平面需重新生成、验解 | 已有标准点灯后端；主题重绘与异形平面尚需实现、核验 |
| 矩形分区 Shikaku | 博古架、窗棂、抽象建筑、几何拼贴 | 矩形划分本身表达建筑秩序；保留矩形、面积数字及每区一个线索等规则。答案分隔线不能先画成题页的架格／窗框；可在解答后补齐造型 | 已有矩形分区后端；主题化答案仍需绘制，不允许弯曲矩形来迁就花瓣造型 |
| 银河 Galaxies／Tentai Show | 星云、对称花簇、晶体、织锦 | 公开中心点可作星核／花心；每个答案区域须绕对应中心旋转180°对称。依赖解答的区域轮廓与纹理只在答案中显现，不在题页先画花瓣边界 | 已有银河后端；指定主题图案的生成与绘制未内置，不保证任意题解自然像花簇 |
| 拼块填形（可新增题型） | 动物、花瓶、叶片、六边形徽章 | 目标外轮廓本身是公开题意；所需拼块及是否允许旋转／翻转需明确。实际铺法属于答案，检查覆盖、重叠及唯一性 | 尚无现成生成链路；不能冒用既有多米诺配对后端，或把候选名称计入已支持题型 |

可优先探索的组合：东方古典的“桥梁—荷叶池塘”“数和—镂空窗棂”，装饰艺术的“地图着色—冰裂瓷纹／彩窗”，赛博朋克的“点灯—城市街区”。这些是推荐起点，用户已选其他主题或自行委托时按实际要求设计。荷叶、花卉等仍按地区与季节核对，不能因推荐组合直接套用全年。

规则依据与设计推论分开：对应基本规则见 [桥梁](https://www.nikoli.co.jp/en/puzzles/Hashiwokakero/)、[数和](https://www.nikoli.co.jp/en/puzzles/kakuro/)、[点灯](https://www.nikoli.co.jp/en/puzzles/akari/)、[矩形分区](https://www.nikoli.co.jp/en/puzzles/shikaku/)、[银河](https://www.nikoli.co.jp/en/puzzles/tentai_show/)、[地图着色](https://www.chiark.greenend.org.uk/~sgtatham/puzzles/doc/map.html)。上述物象配对与呈现方案是本技能的设计建议，不冒称官方题型变体或原厂视觉方案。

## 已运行的形式与边界

| 形式 | 实际变化 | 当前证据与入口 |
| --- | --- | --- |
| 蜂巢数回 | 每格六条边；默认类六边形整体轮廓，保留完整单元形成的自然细锯齿 | 默认 `shape_hex_cluster.py` 先建对称蜂巢簇再出题，独立 Z3 验证；`shape_loopy.py` 无 `--params` 时走同一默认。上游 `5x5t2dh` 的长方形蜂窝阵列仅供用户明确指定该轮廓时使用 |
| 三角数回 | 每格三条边；可选整体等边三角形或上游锯齿轮廓 | `shape_triangle_cluster.py` 可先建等边三角簇再出题，`--side` 支持5／6／7；本次候选样例为边长6、36个三角面，独立验证唯一解。上游 `shape_loopy.py` 已运行 `5x5t1dh`、`7x7t1dh`，仍可显式选择 |
| 圆形迷宫 | 同心环与径向通道，外圈入口至中心终点 | `shape_circular.mjs`；附 MIT Codebox 核心代码。独立 BFS 核对连通、树边数、答案路径并与引擎路径比对 |
| 无框桥梁 | 数字岛屿散布在纸面，省去整体外框 | 复用已有 hashi 后端；`shape_boards.py`按原坐标画岛屿与答案。不能任意移动岛屿，否则改变横竖相邻关系 |

这四种形式属于三个规则家族。上述是可重现的实例级能力；没有接入 `extended_job --types auto` 的形态轮换，也没有完成全年量产、全部种子、人工难度或实物打印验收。需要它们时走独立入口、保存来源与验证，再纳入当前任务。

更进一步的候选：Loopy 的开罗五边形、Penrose、混合镶嵌；Codebox 的三角／六角迷宫及遮罩；Map 的不规则内部分区。上游支持不等于本 skill 已接通。Map 原生外轮廓仍是矩形，不能称为自由外轮廓。遮罩应先作用于生成图，再重新生成和证明连通，不能裁掉已出题内容。

## 生成与保存

`PYTHON`、`NODE`、`SKILL_DIR`、`SOURCE_PROJECT` 由当前环境解析；所有输出目录须为新目录。

### 蜂巢／三角数回

未指定蜂巢整体轮廓时：

```text
PYTHON SKILL_DIR/scripts/shape_loopy.py --source-project SOURCE_PROJECT --output-dir NEW_JOB --seed USER_SEED
```

默认蜂巢先生成近正六边形的37格簇；可直接用 `shape_hex_cluster.py --radius 2` 生成19格较疏版本。轮廓先于题目产生，重新求解并证明唯一；不裁剪旧题、不直接继承旧题的Hard标签，人工难度仍需校准。

用户明确选择上游长方形蜂窝阵列时加 `--params 5x5t2dh`；三角网格加 `--params 5x5t1dh` 或 `7x7t1dh`。

等边三角形是可选候选，不自动替代既有三角样式：

```text
PYTHON SKILL_DIR/scripts/shape_triangle_cluster.py --source-project SOURCE_PROJECT --output-dir NEW_JOB --seed USER_SEED --side 6
```

`--side` 只接受5／6／7，分别构成25／36／49个完整三角面。先生成完整等边三角图结构，再生成线索与答案，并独立证明唯一解；它是新题，不能通过裁掉旧题边角得到，也不能继承旧题难度评级。样式是否已选以当前项目的真实用户决定为准；人工难度与实物试印分别记录，不因样式认可而视为通过。

`SOURCE_PROJECT` 是 [扩展后端](backends.md) 的只读来源项目。默认蜂巢簇与可选等边三角簇通过已配置Z3独立验证，不需要原生C编译；上游网格变体另需原生loopy、libcore.a、版本匹配源码与C编译器，小型几何导出器只在新输出目录编译。原生网格仅允许上述三个确切参数，未审读参数拒绝。

保存的 `record.json` 包含真实图结构、面内心与线索、答案、seed、参数或轮廓规格、来源文件哈希及新鲜证明。`public.json` 不含答案。验证要求面周边计数、顶点度为0或2、单个非空连通闭环；指定答案 SAT 之后，还须排除完整边答案得到 UNSAT。超时或未知不通过。

### 圆形迷宫

```text
NODE SKILL_DIR/scripts/shape_circular.mjs --engine-dir SKILL_DIR/assets/codebox-maze --output-dir NEW_JOB --seed 20270103 --layers 7
```

无需 npm 安装或联网；附带的是固定版本的 MIT 原始核心文件及许可／哈希清单。显式传其他可信本地 engine 时，应重新审查并保留其来源哈希。

输出公开题面 JSON／SVG、独立答案 JSON／SVG、图结构与证明。图必须全连通且边数为节点数减一，入口至终点的答案须逐边合法，与独立 BFS 一致。当前允许3–12层是接口范围，不代表所有密度都适合A5：已试跑3／7／9层；76毫米、7层示例的径向通道约5.43毫米，最小非中心内弧约4.26毫米，仍需检查线宽扣除后的有效通道。

### 矢量排版

`shape_boards.py` 提供 `draw_loop`、`draw_circular`、`draw_bridges`，供当前 PDF 组版调用；输入 box 为 PDF points 的 `(x, y, width, height)`，坐标原点在左下。它负责绘图，不代替求解器。先通过匹配验证，再绘制。

三个绘制函数均保持 `style='classic'` 默认值。以下是可供比较的候选，只在用户已选定或制作候选样页时显式启用，不能把试作当成用户已认可的默认风格：

| 调用选项 | 视觉处理 | 必须保持的内容 |
| --- | --- | --- |
| `draw_loop(..., style='refined')` | 以真实外缘与内网格的层次突出整体轮廓，不额外套框 | 全部节点、候选边、面线索和答案；强调的外缘不能被画成已选中的答案线 |
| `draw_bridges(..., style='black-islands')` | 黑色岛屿配白色数字，让离散岛群形成清楚的黑白构图 | 岛心与 `classic` 完全相同，横竖相邻关系不变；岛间保留可画单桥／双桥的净空，答案不能穿过数字 |
| `draw_circular(..., style='medallion')` | 整体旋转至入口朝下，强调真实外圆壁与中心目标 | 题面、入口、中心、所有墙段及答案一起旋转，保留原通道和入口断口；不能只转题目或额外增加封闭圆环 |

以上绘制选项不重新出题。圆形迷宫旋转后仍须核对原墙段与答案对应；桥梁更换岛屿外观后须检查实际净空，不能以保持岛心为由省略落笔空间检查。已有用户选择直接沿用，未定的候选先供比较；独立验解与数字版核查不等于人工难度或实物试印已验。

- 常规适配等比缩放整个结构，不把蜂窝横向拉扁来塞版面；用真实面内心定位数字。有意的主题造型可使用已核对的结构保持映射，并重新检查各派生区域的数字归属、净空与落笔面积。
- 环形通道及答案用弧线保持原结构；相邻环道之间连接才用径向线。保留入口与目标。
- 题页只画公开线索；答案层只在独立答案页／用户选定的答案位置绘制。
- 玩法按用户选择单独提供。规则用“区域周围的边”，不能继续写成“四边”“只画横竖线”。
- 量取边长、面内净空、岛屿间距与环道窄处，而非只报外接框尺寸。

新题使用新答案映射；不能继续套用旧题二维码。若本次只做形态样页，可用明确对应的独立答案册；用户选择联网答案时再为新题发布、生成并实测匹配二维码。

## 设计与内容比较

单纯换色／去装饰外框时，保留已冻结的题面和答案。用户要求从方格改为六角或圆形真实结构时，这是新题／规则变体，须另建记录并验解，不冒充原题换皮。比较形态可保留同一日期和信息模块，明确所用是不同样题，未经选定不替换正式排程中的冻结题。

按实际导出PDF检查：所有节点、边、面线索是否保留，答案是否正确对应，断边是否只是截图缩放造成；先看整页，再放大最密单元。去掉整体外框不等于删除规则边界。一般不需要为了“有设计感”额外画方框把自由轮廓重新包起来。
