# Puzzle Calendar 谜题日历

把“用户怎样使用”转成有判断的日历设计，再交付日期正确、题目可解且不重复、便于阅读和落笔的真实文档。默认中文，制作记录可用英文技术字段。
本 skill 同时负责需求、设计、内容、验收与交付；不能以一份题库、规范、效果图或安装成功代替成品。

## 1. 先理解使用情境

先读对话、现有任务与成品，确认用户是在制作日历、改已有日历，还是修改这个 skill。
只补问会改变结果的缺口：给谁用、怎样翻看和解题、时间范围、打印条件，以及用户最在意什么。
不要让用户先决定字体、字号、JSON字段或所有功能；把技术选项转成少量有意义的取舍。
已知或已委托的事项直接沿用；相对年份按当前日期及时区转成绝对范围，不默认365天。
需求细节与提问示例见 [需求与决策](references/intake.md)。
答案与玩法分开选择，支持提出纸质背面、图形或文字答案二维码、独立册子、首玩前规则页及自定义方案；安排与实际能力边界见 [答案与玩法交付](references/answer-and-rules.md)。
二维码是可选项。用户选择联网图形答案后，可按 [Cloudflare 答案托管流程](references/qr-cloudflare.md) 使用其自己的账户发布查看与下载页；未选择时继续纸质方案。

## 2. 写制作简报，建立任务

在 `job.json` 保存唯一需求源；`request.requirements` 存实际值，`decisions` 只存来源与理由。
用 `brief` 说明用途、信息优先级、设计理由、区域关系与取舍，不能只列配色和风格名称。
视觉留白、普通随手记空间与专用记录／跟踪分别定义；空白、横线或点阵是外观，不代表用途。普通记事不以启用解题记录为前提，具体见 [需求与决策](references/intake.md#书写空间与专用记录)。
区分通用正确性约束、该项目已选偏好和当前工具限制；一次项目的黑白、孔区、竖排或寄语不泛化为所有日历。
当前交付可以是全年计划的某月或样页，显式记录 `request.scope`，不把子集说成全年完成。
通过 [任务流程](references/workflow.md) 的 init／prepare／status 维护任务；已有底层脚本继续可用。自定义样页的记录格式不等于helper的2.0合同，接入与迁移按该文档登记，不能仅凭文件名job.json宣称可续做或可发布。
关键中间件、字体解析、源题板与证据注册进任务，不依赖聊天记忆或 `work/` 临时装配脚本续做。

## 3. 先核实能力，再选择方案

读取 [运行能力](references/runtime.md)，按三层说明：已运行实现、需现成依赖／数据、需要本次新增实现。
根据实际能力与纸幅做方案，不把35个候选目录条目、7种daily预设或第三方API都称为任意场景稳定支持。
当前预设是设计起点，不是审美边界；周／月、横版、页内规则或其他纸幅不适配时，换合适实现或明确冲突。
混合题型按受众、节奏与可验证能力安排轮换；不默认只用三类，也不为凑种类牺牲适合性。
使用扩展题型时优先查看已配置的profiles；挑战选择同时考虑真实的Hard、Tricky、Extreme等来源档位，不把Hard名称当成唯一入口。自动选题用`extended_job.py --types auto --difficulty challenge`，保留来源档位和排除原因；新题仍逐题验解与检查版面。
题型能力查 [后端](references/backends.md)，可选日历信息查 [信息模块](references/calendar-information.md)。
题盘不默认方形：按玩法选择六边／三角网格、圆形通道、自然轮廓或无整体外框，选型、已验证实例与生成入口见 [题盘形态](references/puzzle-forms.md)。区分规则家族、网格结构、整体轮廓与边框处理，不把换框或同族变体当成全新题型；更换真实结构需要重新出题与验解。
蜂巢数回未指定整体轮廓时，优先紧凑、均衡、近六向对称的类六边形蜂巢；不要默认排成长方形蜂窝阵列。用户明确指定其他轮廓时尊重其选择，先确定完整单元组成的轮廓，再生成和验证题目。
事实信息先取得地区、年份、时区和可靠来源；排版合同通过不等于事实已核。
只有选定专业个人排盘时才收集必要出生资料，接口与限制见 [专业排盘](references/professional-charts.md)。

## 4. 先试样，再确认风格

候选全部不满意时，按 [全部候选都不满意时](references/intake.md#全部候选都不满意时) 区分题材与表现问题，允许无具象主题，以局部偏好和小样继续探索；不靠重复主题菜单收敛。

用“看图找偏好 → 拆解反馈 → 定向调整 → 真实样页确认”逐步收敛；不要求用户先说出风格名称。分别了解繁简程度、主题气质、具体喜欢的部分、配色与题盘参与程度，沿用已有选择，具体问法与确认边界见 [不知道风格时](references/intake.md#不知道风格时)。
已有任务优先从当前冻结记录选代表题。风格未定时先做少量同日、同题、同信息、同纸幅的比较样页，再由用户选定，之后制作整月或全年。用户只说“你推荐”“都试试”或“试试蓝色”，授权的是推荐或探索，不代表已选某套风格；已确认方案直接沿用，只有明确委托自主定稿并继续批量时才跳过选择。
先定每个候选的主视觉、构图、字体角色和图形语言，让日期、装饰与题面成为整体；不只换字体颜色，也不把零散叶片、圆圈贴到相同模板。数量按需要，用户要求多个方向时不机械限于三款。
繁简是页面关系的设计要求：重新安排主视觉、黑白／色块面积、信息层级与留白，不靠从极繁稿中删图案来得到适中稿，也不靠堆饰解决“没特色”。不受既有候选风格限制；主流品牌、畅销款或趋势只用于提出有依据的候选，不能代替当前用户选择。
涉及极繁、丰富插画或陌生主题时，先按 [极繁设计方法](references/maximal-design.md) 完成主题与题型匹配、构图和细节层级、配色与字体分工、可写空间及素材分工的简报，再生成素材。题型未定时择优匹配；题型已冻结时保留原题。参考图提炼成可迁移的视觉语言，不把几个题材变成用户的固定菜单。
题面也参加设计：在基础外形上，按用户喜欢的风格组织线条、填充、圆圈／节点和整体轮廓。用户希望题盘拟物时，可让题盘成为主题意象，例如东方古典风的蜂巢数回探索莲蓬；保留标准题盘、与精细边框协调也可成立。把规则结构与视觉外观分开：允许不改变题意的柔化和位置映射，保护线索归属、邻接关系、可读性与作答面积；比较完整页并附题面近景。设计方法、莲蓬示例与核对要求见 [设计评审](references/design-review.md#让题盘本身表达风格)。
用户希望题盘成为主视觉时，可参考 [题盘与主题造型融合](references/design-review.md#题盘与主题造型融合主体细密书写区留白)：用主体结构组织细节，并为落笔及已选书写模块保留真实空间。“好看”与“达到所需繁简程度”分别记录，不把前者当成极繁达标或批量风格选定。
主题造型不只限于数回与迷宫，按 [题型与主题造型](references/puzzle-forms.md#题型与主题造型储备) 选择相容方向；优先让题面本身形成完整主题；解答后显现只作少量点缀，不作为默认方案或与题面即显平均分配。双阶段也以题面成立为前提，不靠答案补救平淡题页。依赖答案才能确定的边界、连线、填色与主题细节只放在所选答案载体，先核对是否泄题，方法见 [主题的呈现阶段](references/design-review.md#主题的呈现阶段)。这些方向是设计储备，不因收录而变成已内置生成能力。
主题物按地区、季节、生长阶段或具体节庆匹配日期，并复核画面状态；适用窗口、用户指定例外及旧样页边界见 [主题物与日期对应](references/design-review.md#主题物与日期对应)。
必要时先用已核实的参考图或概念图确认大方向；概念PNG、真实可打印PDF、用户风格确认分开标明。图像生成可用于原创插画或配色探索，正式日期与谜题必须从可靠结构数据排入并核对，不能把生成比较图直接当成已验收日历。
风格备选与来源见 [风格库](references/style-library.md)、[设计研究](references/calendar-design-research.md)。所选风格与配色、题面处理对应当前候选版本，确认范围和真实用户反馈记入任务，不能凭内部判断填认可。
“还可以”“比之前好”“这个有趣”是改善反馈，不自动表示定稿。保留已认可的部分，集中处理主要未决项；从概念收敛后，以目标尺寸、准确日期、真实题面及所选答案安排制作代表样页，明确本次选定的版本和可继续范围，不把风格确认、最终成品验收、实物试印和真人难度混为一项。已有明确选定和继续授权时不重复索取同一确认。
确定方向后，用最终渲染链路检查拥挤页、长题名、外部线索、规则首现等实际风险，附对应答案与必要规则。按 [打印验收](references/print-design.md) 检查安全区、字形、格距、线宽、嵌入与最终PDF画面；这些内部检查不替代用户风格选择。

## 5. 确认后生成并冻结正式内容

日期计划可以先算，风格比较只生成必要样题；确认或明确委托定稿后才批量制作当前范围。
用日期planner计算年月日、星期、题位和题量，不能由文案覆写；周一至周五不等于法定工作日。
农历、节气、放假调休按可靠数据核对；未发布的年度安排保留未知，不按往年推定。
逐题生成、新鲜求解、独立规则验解、完整唯一性证明、全局去重及难度记录，合同见 [内容](references/content.md)。
只接受证明完整的 `UNIQUE`；找到一解、超时、未完成搜索都不能称唯一。
跨月、分批、恢复与换题共用记录；精确去重、已实现等价检测和视觉相似筛查分别说明覆盖范围。
难度区分上游程序档、统一评级与真人试玩；有Hard参数不等于已证明人人觉得有挑战。
在明确预算内重试，失败保存缺口与进度，不用重复或未验证内容补齐。
样题认可或被要求保留后，冻结题面、答案、规则版本、seed、稳定ID及日期；换风格不换题。

## 6. 按影响修订与续做

反馈先归入需求、设计、内容或交付；更新任务并写明原因，不另建一份相互矛盾的需求摘要。
用 revise 返回影响范围并使相关证据失效；文件哈希改变后不能沿用旧PDF、旧预览或旧检查冒充新版通过。
文字／字体／样式修改保留原题，只重排受影响页；换题只重验指定题并与全局账本去重。
改范围、频率、纸幅或装订时重算受影响的日期、配额与适配，不因局部改动重做全部已认可内容。
重用记录须新鲜核对题面、答案、唯一性和资产哈希；路径迁移后恢复相对资产映射，缺失则明确报告。
用户已经作出的决定不反复追问；只在真实冲突或关键缺口改变结果时提出选择。长任务说明当前正在出题、验解、渲染还是发布；失败时报告具体步骤，保存已完成部分，按预算换方案或说明阻塞，不能无限重试或把未启动的步骤说成正在等待。

## 7. 证据闭环后交付当前范围

注册最终PDF、必要规则、答案、预览、说明与制作资料，分别保存content／pdf／visual检查及实际覆盖范围。
预览绑定当前PDF哈希；视觉记录说明查看的页面、五项标准、发现与修复，不只写“好看／passed”。
风格选定是批量制作前的设计决策；最终成品验收、实物试印与真人难度另记。没有证据不能填通过，样稿可供选择；不额外增加已确认用户的重复审批。
当前 release 按角色生成题本包、独立答案包与私有制作包；其他答案安排须按 [答案与玩法交付](references/answer-and-rules.md) 实现和核对，不能套用旧打包结果冒称完成。
完整答案只出现在用户选定的答案区域或直接存答案的二维码中；不额外藏入题本元数据、附件或隐藏层。内部ID可以不印，但题目、答案与实际位置的映射不能丢。
合法pending结果可标明trial交付；打包成功不等于 `digital_ready`，更不等于用户认可或实物印刷通过。
数字交付说明实际页幅、100%打印、单双面／装订方式及已检查范围，不声称普通PDF是印厂认证。
最终链接真实文件，明确当前完成范围、仍未知的数据与剩余事项；不要把一月或样页称为全年的完成品。
